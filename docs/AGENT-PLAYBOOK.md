# Agent 构建方法论（从 0 到发布的全流程）

> 沉淀自 [traffic-analysis-agent](https://github.com/LetheYYY/traffic-analysis-agent) 项目的完整实战（部署 → 架构 → MVP → 评测 → 调优 → 文档 → 开源发布）。
> 目标：做任何 Agent 项目时按本方法论直接复用，避免重复踩坑。

## 总览：八个阶段

```
P0 约束盘点 → P1 选底座 → P2 部署验证 → P3 架构理解 → P4 MVP → P5 评测基线 → P6 调优闭环 → P7 文档 → P8 发布
```

**核心原则**：最小闭环先行（先跑通再完善）· 数字驱动（每阶段有可验证产出）· 全程可复现（脚本化）· 可回滚（基线 + 断点续跑）。

---

## P0 · 需求与约束盘点（30 分钟）

| 项 | 问什么 | 产出 |
|---|---|---|
| 任务定义 | 输入/输出/使用场景（交互 or 批处理） | 一句话目标 + 输入输出规格 |
| 硬件 | CPU/内存/GPU/磁盘 | 硬件约束表 |
| 软件 | Node/Python/关键 CLI 是否就绪 | 环境清单 |
| 网络 | npm/pip/GitHub/API 端点是否可达（**实测**） | 网络可达性表（决定镜像/代理策略） |
| 模型策略 | 云端 API or 本地模型 | 决策（硬件差→云端；数据敏感→本地小模型） |

## P1 · 选底座框架

评估清单（不只看 star）：

- [ ] 插件化/可扩展：能力能否不加代码扩展（技能/工具/适配器）？
- [ ] 运行形态：交互（web）+ 批处理（headless）是否都有？
- [ ] 技能系统：能否注入领域知识？如何发现/加载？
- [ ] 可导出/分发：做好的 agent 能否打包给别人？
- [ ] 模型无关：能否换 API/本地端点？
- [ ] 许可证与活跃度（MIT 优先、近期有 commit）
- [ ] 官方文档质量

## P2 · 部署与验证

**标准动作**：装依赖 → 构建 → 冒烟测试。

**高频踩坑与解法**（实战验证）：

| 坑 | 解法 |
|---|---|
| npm/pip 直连超时 | 换镜像源，项目级 `.npmrc` |
| 构建脚本要 git commit | 解压源码非 git 仓库 → `git init` + 首次提交 |
| 从项目目录启动报模块解析错 | tsx 按 cwd 找 tsconfig → `TSX_TSCONFIG_PATH` 显式指定 |
| Agent 工作区 = 进程 cwd | 启动器 `cd` 到项目根 |
| 无 API Key 无法验证 | 用框架自带 mock LLM 跑通全链路（重要！） |
| 大文件解析慢 | 流式解析 + 轻量模式（跳过逐包深度解析） |

**验收标准**：配置树 dump 完整 + headless 冒烟一次通过 + 会话日志落盘。

## P3 · 架构理解（先理解后写码）

1. **分层心智模型**：表层（交互/批处理）× 能力层（技能/工具/preset）× 内核（循环/会话/权限/路由）
2. **文档驱动**：读官方 docs，不猜
3. **画图**：自画分层图，梳理"每层放什么、箭头什么关系"
4. **提前摸清导出机制**：怎么打包/分享做好的 agent

## P4 · 最小可用版 MVP

**最小闭环**：输入 → agent → 工具 → 输出 → 存档。

1. **技能先行**：把领域知识写成技能文件（SOP / 命令库 / 特征 Checklist / 输出规范）——性价比最高的质量提升手段
2. **工具策略**：优先复用现有 CLI（shell 直调），不够再写专用工具
3. **测试数据自造**：写生成脚本（含真实场景特征），保证可复现
4. **归档规范写进技能**：让 agent 自己写报告/更新文档（自运转）
5. **验收**：真实跑通一次完整任务 + 输出归档

## P5 · 评测与基线

1. **数据集**：找标准数据集 + ground truth（搜索：领域 + benchmark + LLM agent）
2. **评测脚本要点**：
   - 自动化批量 + **断点续跑**（结果增量落盘）
   - 超时处理：**必须杀进程树**（否则子进程占管道卡死）
   - 输出解析：JSON 提取 + 兜底正则；解析失败自动重跑
   - **评分口径先定**：GT 缺失字段跳过 vs 判错——口径错会让成绩虚低（本项目实测偏差 40pp+）
3. **实时监控**：独立窗口实时显示进度（读结果文件，与评测进程解耦）
4. **产出**：基线数字 + 逐事件明细（可复现）

## P6 · 调优闭环（迭代）

```
失败案例分析 → 分类归因 → 最小改动 → 同口径 A/B 复测 → 图表对比 → 固化基线 → 下一轮
```

**归因分类**（先分清楚再动手）：
- 规则问题 → 改技能（判定规则、命名粒度、证据强度）
- 语义精确性问题 → 评分端归一 + 输出规范
- 数据/环境问题 → 超时重试、协议提示
- 随机性 → 重跑确认，不 panic

**原则**：先技能/提示词（零成本），再考虑换模型/加工具（高成本）；每次只改一处可验证的东西。**图表化对比**（准确率/命中分布/失败分类）每次迭代都出。

## P7 · 文档与知识管理

- **双轨**：仓库 README（对外）+ 个人知识库（对内）
- **让 agent 自己写**：技能规定"完成后归档报告/运行记录/总览"→ 文档自动生长
- **图表**：Mermaid（知识库原生）+ SVG（GitHub 可靠渲染）
- **数字入库**：每轮评测结果写入文档，形成可追溯历史

## P8 · 开源发布

1. **敏感信息审计（必做）**：公司名/内网 IP/域名/样本标识/Token/个人标识——全库 grep 清单化扫描
2. **入库策略**：第三方源码、大体积依赖、许可不明数据集 → gitignore + 脚本拉取；README 说明
3. **致谢**：参考过的开源项目列表（名称 + 用途）
4. **发布路径**：git 协议不通时用 Contents API 上传（base64）；私有→公开一键切换
5. **凭据安全**：对话中出现过的 Token 建议轮换；脚本只从环境变量读凭据，不落盘
